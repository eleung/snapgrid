# API Overview

A map of the public surface. Follow a link for details.

## `@snapgridjs/solid`

The main package. Hooks (the headless layer), turnkey components, and a re-export of the engine
types. Headless grids render inside a dnd-kit `DragDropProvider`; `<GridLayout>` bundles one.

### Hooks (headless)

Every hook returns Solid **accessors** (`Accessor<T>` from `solid-js` — call them, e.g. `style()`)
plus **ref callbacks** you bind with `ref={tile.ref}`. Keep the handle object and read its fields
inside JSX or an effect so they stay reactive.

| Export | Returns |
| --- | --- |
| [`useGridContainer`](/solid/docs/api/hooks#usegridcontainer) | `{ ref, style, isDropTarget, group, controller }` — the grid host |
| [`useGridItem`](/solid/docs/api/hooks#usegriditem) | `{ ref, handleRef, style, isDragging, item }` |
| [`useGridResizeHandle`](/solid/docs/api/hooks#usegridresizehandle) | `{ ref, handleProps, isResizing }` |
| [`useGridPlaceholder`](/solid/docs/api/hooks#usegridplaceholder) | `Accessor<GridPlaceholderInfo \| null>` — `{ item, style }` or `null` |
| [`useContainerWidth`](/solid/docs/api/hooks#usecontainerwidth) | `{ width, mounted, ref }` |
| [`useResponsiveLayout`](/solid/docs/api/hooks#useresponsivelayout) | `{ breakpoint, cols, layout, onLayoutChange }` |
| [`useGridController`](/solid/docs/api/hooks#usegridcontroller) | `GridController` — own a grid's controller without a surface |
| [`resolveController`](/solid/docs/api/hooks#resolvecontroller) | `GridController` — resolve a grid by its `group` |

### Components (turnkey)

| Export | Purpose |
| --- | --- |
| [`GridLayout`](/solid/docs/api/components#gridlayout) | Drop-in controlled grid with a render-prop child (bundles the provider). |
| [`ResponsiveGridLayout`](/solid/docs/api/components#responsivegridlayout) | Per-breakpoint layouts. |
| [`GridItem`](/solid/docs/api/components#griditem) | A positioned tile with default markup + handles. |
| [`GridPlaceholder`](/solid/docs/api/components#gridplaceholder) | Default landing-cell marker. |
| [`SnapGridGroup`](/solid/docs/api/components#snapgridgroup) | Shares one provider across sibling grids (cross-grid). |

### Re-exported dnd-kit primitives

For convenience (one import source), `@snapgridjs/solid` re-exports the dnd-kit pieces you commonly
reach for with a grid: `DragDropProvider` (the drag context headless grids render inside),
`DragOverlay` (an optional separate floating preview), `useDraggable` / `useDroppable` (e.g. an
external-drop palette), and `Feedback` / `PointerSensor` / `KeyboardSensor`. Import them from
`@snapgridjs/solid` rather than directly from `@dnd-kit/*` so they share snapgrid's single dnd-kit
instance — a second copy of `@dnd-kit/solid` is a separate `DragDropProvider` context, and drags from
it never reach the grid.

There's no overlay component to reach for: a dragged tile
[floats itself](/solid/docs/guides/headless#floating) (dnd-kit lifts it into the top layer), so the common
case needs nothing extra. The re-exported `DragOverlay` is the escape hatch for when the floating
preview must differ from the tile — a clone, a ghost, or wholly custom markup.

To nest a non-grid drop zone inside a grid, `nestedDropCollisionDetector` and
`SNAPGRID_DROPPABLE_ATTR` are exported too — pass them to your own `useDroppable` so the zone
outranks the grid it sits in (innermost-wins). See the [nesting guide](/solid/docs/guides/nesting).

### Interop

`snapMove(layout, event)` — the reducer for [dnd-kit interop](/solid/docs/guides/dnd-kit-interop):
place a dragged item (a foreign `useSortable` card, or a tile crossing a grid ⇄ list seam) into a
`Layout` at the pointer cell, with compaction. It resolves the destination grid's geometry and
compactor from the grid under the pointer, so the optional context is override-only. Pair it with
`removeItemWithCompactor` to take a tile back out. Types: `SnapMoveContext`, `SnapMoveEvent`.

### Utilities & compactors

`DEFAULT_BREAKPOINTS`, `DEFAULT_BREAKPOINT_COLS`, and the built-in compactors
`verticalCompactor`, `horizontalCompactor`, `noCompactor`, `getCompactor`. Plus the layout-op and
geometry helpers handy for interop, re-exported from `@snapgridjs/core`:
`insertItemWithCompactor`, `removeItemWithCompactor`, `toPositionParams`, `defaultGridConfig`.

### Types & config

`Layout`, `LayoutItem`, `GridConfig`, `DragConfig`, `ResizeConfig`, `DropConfig`, `GridDropData`,
`GridEventCallback`, `Compactor`, `CompactType`, `Breakpoints`, `BreakpointCols`,
`ResponsiveLayouts`, `PositionParams`, `ResizeHandleAxis`, `DragSourceInfo`. See
[Types & config](/solid/docs/api/types).

The binding's own option/result types are exported too, named after their hook or component:
`UseGridControllerOptions`, `GridContainerResult`, `UseGridItemOptions`, `GridItemHandle`,
`GridPlaceholderInfo`, `UseGridResizeHandleOptions`, `GridResizeHandle`,
`UseResponsiveLayoutOptions`, `ResponsiveLayoutHandle`, `UseContainerWidthOptions`,
`ContainerWidthHandle`, `GridLayoutProps`, `ResponsiveGridLayoutProps`, `GridItemProps`,
`GridPlaceholderProps`, and `GridItemRenderer`. See [Hooks](/solid/docs/api/hooks) and
[Components](/solid/docs/api/components).

## `@snapgridjs/core`

The framework-agnostic layout math: geometry, move/resize/insert/remove operations, and the drag
session state machine. Most apps never import it directly. See
[Core engine & extras](/solid/docs/api/core).

## `@snapgridjs/dnd`

The framework-agnostic dnd-kit engine `@snapgridjs/solid` is built on — one per-manager
drag/resize/cross-grid engine (`attachEngine`), the observable `GridController` render bridge, the
`snapMove` interop reducer, and the collision/sensor/payload helpers a binding wires up. Comes in
automatically with `@snapgridjs/solid`; import it directly only to build a binding for another framework.

## `@snapgridjs/extras`

Optional packers: `masonryCompactor`, `gravityCompactor`, `shelfCompactor`, plus `wrapCompactor`
and the fast O(n log n) compactors re-exported from react-grid-layout. See
[Core engine & extras](/solid/docs/api/core#snapgridjsextras).
